# CRM

CRM использует существующие таблицы клиентов, адресов, счетов, тарифов, платежей и инцидентов. Она связана со звонками и обращениями по клиенту и лицевому счёту. Сервер читает суммы в копейках и передаёт даты с часовым поясом.

## Кабинет руководителя

На странице /customers доступны поиск по ФИО, телефону и любому лицевому счёту, фильтр по статусу, сортировка и постраничная выдача. Строка показывает первый лицевой счёт по номеру, адрес, тариф, баланс и последнее обращение. Ссылка открывает подробности клиента рядом со списком. Параметры списка и выбранный счёт сохраняются в URL.

В карточке показаны контакты, лицевые счета и данные выбранного подключения. Вкладки охватывают обзор, счета, платежи, звонки, обращения и заметки. Инциденты выбираются по адресу счёта. История использует фильтры клиента и выбранного счёта. Заметки относятся ко всему клиенту. Изменения платежей, тарифов и услуг, а также отдельный реестр договоров требуют дополнительных контрактов. ## API

| Маршрут | Данные |
| --- | --- |
| `GET /api/v1/customers` | `q`, `status`, `sort`, `order`, `limit` и `offset`. Ответ содержит `items`, `total`, `limit` и `offset`. |
| `GET /api/v1/customers/{customer_id}` | Карточка клиента, все счета и данные каждого подключения. |
| `GET /api/v1/customers/{customer_id}/notes` | Заметки клиента, начиная с новых. Каждая содержит `id`, `text`, `author_name` и `created_at`. |
| `POST /api/v1/customers/{customer_id}/notes` | Сохраняет заметку и возвращает её с `201`. Текст после удаления пробелов по краям должен содержать от 1 до 4000 символов. Автор определяется по сессии руководителя. |
| `GET /api/v1/calls` и `GET /api/v1/tickets` | История с фильтрами `customer_id` и `account_number`. |
| `GET /api/v1/operator/customers/{customer_id}` | Контакты и только счета, связанные с доступными оператору звонками или обращениями. Недоступный клиент возвращает `404`. |

Дата последнего контакта в общем списке берётся из последнего звонка или создания обращения. Для оператора учитываются записи, к которым у него есть доступ. Рабочие заметки оператора относятся к звонку и хранятся в Contact Center. Голосовой процесс запрашивает подтверждённый счёт текущего звонка через сервисный API.
