# Contact Center IRIS

Contact Center использует существующие таблицы звонков, обращений, сотрудников и журнал событий. Лицевой счёт и его данные читает модуль CRM. Идентификатор счёта в Voice API называется `account_id` и соответствует существующему `accounts.number`.

## Запуск на временной SQLite

Для нового файла схема создаётся при первом запуске FastAPI. Contact Center включён по умолчанию. Укажите новый временный `DATABASE_PATH` и `IRIS_DEMO=1` для учебных данных. Для существующей SQLite выполните миграцию на копии. [Запуск](../README.md#запуск-демо) · [Миграция SQLite](DATA_MODEL.md#миграция-sqlite)

Кабинеты используют сессионный cookie. Совместимые маршруты из таблицы ниже требуют заголовок `Authorization: Bearer <токен>`. Задайте `IRIS_OPERATOR_TOKENS` как JSON-объект с соответствием уникальных токенов идентификаторам сотрудников. `IRIS_VOICE_TOKEN` задаётся отдельно для доверенного процесса Voice. [Роли и разрешения](ROLE_PERMISSIONS.md) · [Voice API](VOICE_CORE_INTEGRATION.md)

## Очередь живых звонков

Входящий звонок проходит `ringing → active → completed | abandoned | failed`. После ответа ИИ фаза `ai_active`. Запрос передачи переводит звонок в `waiting_for_operator`. Принимая предложение, оператор переводит звонок в `operator_joining`. Событие Voice подтверждает звук и переводит звонок в `with_operator`. При завершении Core освобождает живую очередь и сохраняет бизнес-результат отдельно от технического статуса. Закрытие обращения выполняется отдельно.

Очередь сортируется по приоритету, времени постановки и идентификатору. Среди сотрудников подходящего отдела с нужными навыками Core выбирает дольше всех свободного. Сотрудник должен быть на смене со статусом `available` и без живого назначения. Транзакция SQLite `BEGIN IMMEDIATE` и уникальные индексы защищают пару «звонок — сотрудник» от двойного назначения. Предложение по умолчанию действует 15 секунд, подключение после принятия — 30 секунд. Настройки `IRIS_ASSIGNMENT_TIMEOUT_SECONDS` и `IRIS_CONNECTION_TIMEOUT_SECONDS` задаются в секундах.

При истечении срока, отказе оператора или сбое подключения звонок снова ждёт в очереди. Core пробует другого сотрудника, а прежний снова участвует в маршрутизации того же звонка после перехода обратно в `available`. Обработчик API проверяет сроки примерно раз в секунду. При перезапуске он читает сохранённые сроки из SQLite. Позиция считается среди ожидающих звонков отдела. API отдаёт прошедшее время ожидания. Для прогноза времени потребуется история обслуживания.

## Специализации операторов

Руководитель назначает несколько специализаций в разделе «Команда» → «Сотрудники» → «Сведения о сотруднике». Список сотрудников возвращает поле `specializations`. Маршрут `PUT /api/v1/employees/{employee_id}/specializations` принимает полный набор, например `{"specializations":["L1","L2"]}`. Пустой список снимает все специализации. Значение `null` в списке сотрудников означает, что запись относится к другой роли.

Core хранит коды в существующем списке навыков оператора. При изменении специализаций из кабинета сохраняются остальные навыки. Для каждой специализации Core добавляет очередь при запуске, в том числе в существующую SQLite. Категория Voice определяет очередь, а специализация даёт оператору доступ к звонкам этого направления независимо от его отдела. Если подходящих свободных операторов нет, звонок остаётся в очереди. [Категории Voice API](VOICE_CORE_INTEGRATION.md#передача-оператору)

Снятие специализации возвращает в очередь предложение, которое оператор ещё не принял. Принятое назначение продолжается по обычному циклу звонка.

## Отделы и сотрудники

Инициализатор добавляет `technical_support`, `billing` и `connection`. Правила категории, произвольные коды отделов, навыки, роль, компания и признак смены хранятся в базе. Примените JSON с помощью `python -m app.core.contact_center.configure настройки.json` в окружении с нужным `DATABASE_PATH`. Пример для существующего сотрудника `operator_1` приведён ниже.

```json
{
  "departments": [{"code": "L2", "name": "Вторая линия"}],
  "routing": [{"category": "router", "department": "L2", "required_skills": ["network"]}],
  "workforce": [{"employee_id": "operator_1", "department": "L2", "role": "operator", "company": "SkyNet", "skills": ["network"], "on_shift": true}]
}
```

Существующие сотрудники без расширенного профиля считаются операторами на смене. Доступны `available`, `paused`, `lunch` и `offline`. Статусы `busy` и `wrap_up` устанавливает Core. После разговора оператор завершает постобработку отдельным запросом. Компания в профиле используется для отображения команды. Для эксплуатации с несколькими организациями потребуется изоляция их данных и маршрутизации.

## API оператора

Все пути ниже используют префикс `/api/v1/contact-center`.

| Маршрут | Данные или действие |
| --- | --- |
| `GET /dashboard` | Профиль, очередь отдела, последние доступные обращения, инциденты подтверждённого счёта текущего звонка |
| `GET /workspace` | Текущее предложение, назначение и профиль |
| `GET /queue` | Ожидающие звонки отдела и подходящих специализаций без CRM-данных |
| `GET /calls/{id}`, `GET /calls/{id}/account` | Сводка, события, транскрипция и подтверждённый счёт CRM для доступного звонка |
| `GET /calls/{id}/notes`, `POST /calls/{id}/notes` | Собственные заметки. Запись принимает `event_id` и `text` |
| `POST /calls/{id}/confirm-summary` | Отметка о проверке сводки |
| `POST /assignments/{id}/accept`, `POST /assignments/{id}/decline` | Принять или отклонить своё предложение |
| `POST /assignments/{id}/control` | Команда Voice с `event_id` и `action`. Для перевода укажите `department` или `target_employee_id` |
| `GET /cases`, `GET /cases/{id}`, `GET /cases/{id}/events`, `PATCH /cases/{id}` | Поиск по `q`, фильтры `status` и `priority`, карточка, история и смена статуса |
| `GET /cases/{id}/context` | Итог звонка и сохранённая карточка обращения с фактами, предположениями, действиями и открытыми вопросами |
| `GET /cases/queue`, `POST /cases/{id}/claim` | Краткий список свободных обращений отдела и атомарное принятие в работу после завершения связанного звонка |
| `GET /analytics` | Число обслуженных и завершённых звонков, результаты, длительность подтверждённых разговоров оператора |
| `GET /team`, `GET /departments` | Доступность коллег и список отделов |
| `GET /profile`, `GET /profile/permissions`, `PATCH /profile/status`, `POST /profile/complete-wrap-up` | Профиль, возможности роли, статус и завершение постобработки |
| `GET /profile/settings`, `PUT /profile/settings` | Личные настройки `notifications_enabled` и `sound_enabled` для совместимого Bearer API |
| `GET /events` | SSE с заголовком авторизации |

## События SSE

Клиент получает `event: change`, числовой `id` и JSON с `type`, `resources`, `call_id` и `ticket_id`. В числе событий `call.started`, `call.identified`, `call.summary_updated`, `call.transcript`, `call.queued`, `assignment.offered`, `assignment.accepted`, `assignment.connected`, `employee.updated`, `call.ended`, `ticket.created` и `ticket.updated`. Для недоступных звонков уведомление об изменении очереди поступает как `contact_center.refresh` без идентификаторов звонка и обращения. Кабинет перечитывает указанные REST-ресурсы. При переподключении передайте последний обработанный `id` заголовком `Last-Event-ID`.

Для проверки выполните `$env:PYTHONPATH='backend'`, затем `& ./.venv/Scripts/python.exe -m unittest discover -s backend/tests -v`.
